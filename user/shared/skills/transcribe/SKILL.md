# Transcribe — 로컬 파일 Gemini 전사

```bash
python3 ~/.claude/skills/transcribe/scripts/transcribe.py <파일> [--out <경로>] [--anchors [초]] [--speakers] [--smart] [--lang <코드>] [--vocab <용어,...>] [--plain]
```

옵션과 동작은 `--help`가 정본이다. 스크립트가 말하지 않는 것만 여기 둔다.

## 실행 전 확인

- **키**: `GEMINI_TRANSCRIBE_API_KEY`만 읽는다(범용 `GEMINI_API_KEY`는 읽지 않는다 — 다른 과금 프로젝트와 섞이지 않게). 없으면 즉시 오류로 끝나므로 먼저 `echo ${GEMINI_TRANSCRIBE_API_KEY:+set}`로 확인한다.
- **과금**: 입력 토큰만 과금, 분당 약 0.003 USD(46분 실측 0.14 USD, 2026-09-02). 무료 티어는 분당 토큰 한도 때문에 25분 청크마다 대기가 생긴다 — 스크립트가 429 지시대로 기다리므로 그대로 두면 된다.
- **의존**: `curl`, `ffmpeg`/`ffprobe`(25분 초과 분할·영상 오디오 추출).

## 옵션을 고른다

기본은 옵션 없는 verbatim이고 가장 정확하다. 옵션은 사용자의 목적에 필요할 때만 켠다. 사용자가 말하지 않았으면 아래 기준으로 고르고, 결과 보고에 무엇을 왜 골랐는지 적는다.

- **`--anchors`**: 원문 위치 인용이 필요한 경우에만 켠다. 위키처럼 전사문을 나중에 대조하고 인용할 때가 그렇다. word timestamp를 켜는 옵션이고, 공식 문서는 이것이 정확도를 소폭 낮출 수 있다고 경고한다. 실측에서도 같은 클립의 "Kubernetes"가 "Cuba needs"로 바뀌었다(2026-09-21). 강의 노트처럼 본문만 필요하면 끈다.
- **`--speakers`**: 누가 말했는지가 필요한 녹음에 켠다. 회의, 인터뷰, 대담이 그렇다. word timestamp가 함께 켜지므로 `--anchors`와 같은 정확도 저하가 따른다. 화자가 한 명인 강의에는 끈다.
- **`--smart`**: 사용자가 읽기 좋게 정리된 글을 원할 때 켠다. 필러와 반복이 지워지므로 인용이나 발화 분석처럼 원문 그대로가 필요한 용도에는 끈다.
- **`--vocab`**: 녹음에 나올 고유명사를 사용자가 알려 줬거나 대화 맥락에서 알 수 있을 때 넣는다.
- **`--lang`**: 자동 감지가 틀렸을 때만 지정한다.

`--anchors`와 `--speakers`는 `--smart`, `--vocab`과 함께 쓸 수 없다. API 제약이고 스크립트가 요청 전에 오류로 끝낸다. 사용자의 요구가 양쪽에 걸치면 어느 쪽을 포기할지 사용자에게 묻는다.

## 결과 다루기

- 산출물은 확률적 원문이다(ASR). frontmatter `transcript:`가 모델·모드를 남기므로 지우지 않는다.
- 고유명사(모델·제품·인명)는 오청취가 흔하다. 요약·정리에 쓰기 전에 의심되는 표기는 사용자에게 확인한다.
- `--speakers` 없이 만든 전사문에는 화자 표지가 없다. 발언자 구분은 문맥으로 한다.
- 화자 label은 익명이다(`spk_0`, `spk_1`). 이름으로 바꿀 때는 문맥으로 누구인지 추정한 뒤 사용자에게 확인한다.
- 25분 초과 파일은 청크마다 label을 새로 매기므로 `c1-spk_0`과 `c2-spk_0`은 다른 사람일 수 있다. 청크 경계 앞뒤 발언의 내용으로 대응을 맞추고, 확신이 없으면 접두어를 그대로 둔다. 경계에서 잘린 발언은 새 청크에서 `spk_0`부터 다시 시작한다.
- 3명 이상의 화자 구분은 API가 실험적 기능으로 분류한다. 발언이 다른 화자에게 붙은 곳이 있는지 확인하며 읽는다.
