# 한국어 기술 문서 작성

**적용:** Claude가 한국어 산문을 쓸 때. 답변, 문서, ADR, 커밋, PR, issue 코멘트, 리뷰 코멘트, 코드 주석, SKILL.md 전부 해당한다. 영어로 쓸 땐 "언어 무관 규칙" 절만 적용하고 나머지는 무시.

## 원칙

1. **기술 용어는 원어(영어) 우선** — 용어는 프로젝트와 도메인의 고유 개념, 그리고 코드 식별자다(commit, hook, `check-integrity`). 일반 동사와 명사는 한국어로 쓴다("반환한다", "함수"). 널리 굳은 외래어(파일, 서버)는 한글로 쓰고, 경계는 프로젝트 용어집이 정한다. 병기 "한국어(원어)"는 문서 안 첫 등장에서만 하고 이후엔 하나로. 원어 뒤 조사는 발음 기준이다(commit을, API가). 번역어가 두 의미를 떠안거나 오독을 낳으면 원어로 복귀한다.
2. **사전에 없는 낱말은 만들지 않는다** — 접사를 붙이거나(되-, 재-, -화, -성, -어, -체 …) 관용구의 목적어를 바꿔 끼우는("~을 지다") 자리에서 (a) 실재하는 말인지, (b) 그 뜻이 이 자리에 맞는지 확인한다. 한쪽이라도 아니면 만들지 말고 풀어 쓴다. 용어는 원어로(원칙 1), 산문은 여러 낱말로.
3. **한 개념엔 한 용어** — 같은 것을 두 단어로 부르지 않는다. 한 단어가 두 개념을 지칭하면 개념별로 쪼갠다.
4. **용어는 원어, 연결 산문은 자연스러운 한국어로** — 둘이 충돌하면 뜻이 정확한 쪽을 선택한다. 아래 안티패턴을 피한다.

## 번역투 안티패턴

| 번역투 | 고친 것 |
|---|---|
| 이중피동 "되어질/보여질" | "될/보일" |
| have 직역 "~을 가지다" | "~이 있다" |
| "~에 대한/대해" 남발 ("X에 대한 처리") | 직접 연결 ("X 처리") |
| 수동태 직역 "A에 의해 -된다" | "A가 -한다" |
| 무생물 주어에 의지나 인식 동사 "이 함수는 ~를 원한다", "~를 안다" | 사람이나 구체적 주체를 주어로. "반환한다"처럼 동작 서술은 그대로 |

## 과압축 안티패턴

영어식 밀도로 한국어를 눌러 쓸 때 나온다. 판별법: 소리 내어 읽어 설명 없이 뜻이 잡히지 않으면 풀어 쓴다 (전례: llm-wiki 용어 교정 8건, 2026-08-18).

| 과압축 | 고친 것 |
|---|---|
| 명사 나열 조어 "실질 세부", "방법 세부", "창업 폭발" | 조사·용언으로 풀기: "구체적 방법", "창업의 폭발적 증가" |
| 한자어 술어 압축 "X 귀속은 배경지식" | 문장으로 풀기: "X로 특정한 것은 배경지식이다" |
| 은유 압축 "같은 자리에 선다", "층을 보탠다" | 뜻 그대로: "같은 문제를 다룬다", "더한다" |

## 프로젝트 용어집 컨벤션

도메인 용어(예: 장치는 패턴으로, commit은 커밋으로)는 **프로젝트마다 다르다**. 이 전역 규칙엔 담지 않는다. 프로젝트가 용어를 축적하면 그 프로젝트 안(CLAUDE.md 또는 glossary 파일)에 "확립 용어와 전례(왜 이 번역 또는 원어인지)"로 기록하고 재사용한다.

## 언어 무관 규칙

한국어든 영어든 Claude가 쓰는 모든 산문에 적용한다.

### 문장 연결

기호로 절을 잇지 말고, 기호가 숨긴 관계를 말로 쓴다. 표, 코드, 파일 경로, 메뉴 경로, 단위, 타입 시그니처, 제목 구분자("0045 — "), 라벨 구분자("**용어** — 설명"), 인용문 안의 기호는 그대로 둔다.

- **대시(— –)** — 범위는 한국어 물결표(10~12쪽), 영어 en-dash.
- **화살표(→ ← => 등)** — 치환은 "A를 B로 바꾼다", 순서는 "A 다음에 B", 인과는 "A이므로 B", 대응은 "A는 B에 해당한다". 애매하면 "다음에". 단계가 넷 이상이면 번호 목록.
- **슬래시(/), 가운뎃점(·)** — 슬래시는 "또는", "및", "당" 중 하나로 쓴다. 가운뎃점은 같은 자격의 짧은 명사 나열에만 쓰고, 수식어 나열에는 쓰지 않는다.
- **세미콜론(;)** — 쉼표 섞인 나열이면 글머리 목록으로.
- **괄호** — 괄호 안에 완결된 문장을 넣지 않는다.

기호로 쓰인 파일을 편집할 때도 새로 쓰는 문장에는 적용한다. 주변 문체를 따라 쓰지 않는다. 인용문은 원문 그대로 둔다.

### 꾸민 산문(mannered prose)

직접 서술 대신 은유와 수사를 넣는 글. "a parameter worth varying"을 "a dial worth turning"으로, "이 점은 여전히 중요하다"를 "이 점은 제 몫을 한다"로 쓰는 식이다. 글쓴이를 드러낼 뿐 뜻을 전하지 않고, 은유가 끌고 오는 함의를 글쓴이가 통제하지 못해 부정확해진다. 직설적 표현이 있으면 그것을 쓴다. 위 "은유 압축" 항목의 언어 무관 일반형이다.
