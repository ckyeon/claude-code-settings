# 0025 — 퇴사 반납 기준으로 마이그레이션 runbook 개정

[docs/migration-2026-08-31.md](../migration-2026-08-31.md)를 "개인 노트북 재설치" 전제에서 "퇴사로 인한 회사 맥북 반납" 전제로 고쳐 쓴다. 목표가 "빠짐없이 백업"에서 "개인 데이터만 반출, 회사(gigr) 데이터는 제외"로 바뀌었기 때문이다.

## 바뀐 것

- **백업이 tar 한 줄에서 staging 스크립트로.** gigr가 디렉터리 단위(`projects/`)만이 아니라 줄 단위(`history.jsonl`의 81%)·파일 단위(`plans/` 1개)로 섞여 있어 걸러내며 묶는다. 아카이브 안에 gigr 경로가 없는지 검증하는 단계를 포함하고, 2026-08-31 리허설로 확인했다.
- **`file-history/`와 `~/.claude.json`을 아카이브에서 제외.** 전자는 세션 UUID 단위라 gigr 편집 내용이 분리 불가, 후자는 gigr 항목·머신 상태 혼재. 이로써 이전 판의 자기모순(§2 "통째 복원 금지" vs §4 전체 추출)도 해소된다 — 아카이브에 위험물이 없으니 복원은 전체 추출로 단순해진다.
- **직전 리뷰의 Time Machine 전체 백업 권고를 철회.** 홈 전체 백업은 회사 데이터를 통째로 반출하는 셈이라 이 전제에서는 역효과다.
- **인증·키 복원 단계를 runbook에서 뺀다** — 사용자가 필요할 때 직접 한다. `datagrip-projects/playad`는 회사 DB 프로젝트로 판정해 반출 제외.

## 분리 기준

회사 **작업물**(gigr 세션·편집 이력·프롬프트·plan)은 제외하되, 개인 세션에 스치는 gigr **언급**까지 걷어내지는 않는다 — 후자까지 지우려면 개인 세션 자체를 훼손해야 한다.
