# 0137 — transcribe 리뷰 지적 네 가지를 고친다

ADR 0130~0136을 `code-review`로 리뷰한 뒤, 사용자가 고르기로 한 네 가지를 고쳤다.

## 결정

- **캐시는 출력을 다 쓴 뒤 지운다.** 전에는 `transcribe()`가 본문을 돌려주기 전에 캐시를 지웠다. 그래서 그 뒤 `--out` 쓰기가 실패하거나 stdout에서 broken pipe가 나면, 요금을 내고 받은 결과와 캐시가 함께 사라졌다. 이제 `main()`이 파일이나 stdout에 쓰고 stdout을 flush한 다음에 지운다.
- **"25분 초과"라고 적은 세 곳을 "26분 이상"으로 고친다.** ADR 0136 이후 25분에서 26분 사이 파일은 한 청크로 처리되고 화자 label에 접두어가 붙지 않는다. 고친 곳은 `--speakers` 도움말, SKILL.md의 의존 항목, SKILL.md의 화자 label 항목이다.
- **"대기 시각"을 "대기 지시"로 통일한다.** 429의 "retry in 56.3s"는 시점이 아니라 기간이고, 같은 값을 두 용어로 부르고 있었다(`user/shared/rules/korean-writing.md` 원칙 3). ADR 0133의 제목과 요약도 고쳤다.
- **SKILL.md의 "API key"를 "키"로 고친다.** 같은 항목이 이미 "키"라고 부른다.

## Consequences

- Python 3.9.6과 3.14.10에서 가짜 API로 `main()`을 돌려 네 경우를 확인했다. 둘째 청크가 실패하면 첫 청크가 남는다. `--out` 쓰기가 실패하면 세 청크가 모두 남는다. 다시 실행하면 요청 없이 캐시만으로 `--out`에 쓰고 캐시를 지운다. stdout으로 받으면 쓴 뒤 캐시를 지운다.
- 리뷰의 나머지 지적은 지금 동작에 영향이 없어서 고치지 않았다. 5초 여유 값과 duration 패턴의 중복, 끝 청크 규칙이 여러 곳에 흩어진 점, 본문을 끝 300자로 자른 문자열에서 "per minute"을 찾는 점이 그것이다.
