# 0118 — 외부 시스템이 보내는 입력의 형식도 API 문서에서 확인한다

`user/shared/CLAUDE.md`의 "Verify, don't recall" 항목 첫 문장 뒤에 예 하나를 더했다. 외부 시스템이 보내는 입력의 형식도 이 규칙이 다루는 API 사실이고, 테스트 데이터 파일이 아니라 그 시스템의 API schema와 실제로 받은 payload 하나로 확인한다.

## 경위

- 다른 프로젝트 세션이 inbox에 남긴 건의(ADR 0098)에서 왔다. 그 세션은 봇이 받을 입력의 형식을 공개 테스트 데이터 파일의 표기로 판단했다. 테스트 데이터 파일은 한 사례를 메시지 하나로 보여 주고 첨부를 접두어가 붙은 줄로 적었다. 실제 입력은 메시지 여러 개로 나뉘어 왔고, 첨부 주소도 접두어 없이 본문에 왔다. 그래서 봇은 첨부를 하나도 읽지 못했다.
- 플랫폼의 API 문서는 메시지마다 본문 문자열 하나만 주고 첨부 필드가 없다고 적고 있었다. 이 문서는 그 프로젝트 안에 이미 저장되어 있었다. 기존 규칙도 API 사실은 문서에서 가져오라고 적는다. 하지만 그 세션은 "우리 서버가 받을 입력"을 API 사실로 보지 않았다.

## 결정

- 건의가 낸 문장을 그대로 넣지 않고 한 문장으로 줄였다. 규칙은 이미 있고, 빠진 것은 이 경우도 규칙에 해당한다는 연결이다. 그래서 첫 문장 바로 뒤에 두어 "That"이 API 사실을 가리키게 했다.
- "one real payload"를 남겼다. 문서에 없는 세부(그 사고에서는 첨부 주소의 모양)는 실제 채널로 한 번 받아 봐야 알 수 있다.

## Consequences

- `evals/cases`에 이 문장을 재는 case는 넣지 않았다. ADR 0093에서 한 turn짜리 eval은 사고가 난 조건을 재현하지 못했다. 그리고 기준선에서 통과하는 case는 ADR 0091에 따라 규칙을 지우는 근거가 될 수 있다. 테스트 데이터 파일과 API 문서가 함께 있는 fixture로 case를 만드는 일은 후속 작업으로 남긴다.
