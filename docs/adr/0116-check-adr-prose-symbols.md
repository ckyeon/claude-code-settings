# 0116 — ADR 산문의 화살표와 세미콜론을 `bin/check-integrity`가 잡는다

`bin/check-integrity`가 이 ADR부터의 ADR에서 화살표(`→`, `->`, `=>` 등)와 세미콜론을 찾아 오류로 낸다. `user/shared/rules/korean-technical-writing.md`의 "문장 연결" 규칙은 이 기호들이 숨긴 관계를 말로 쓰라고 한다. 표, 코드, 인용문 안의 기호는 그 규칙이 허용하므로 건너뛴다.

## 경위

- ADR 0113을 commit할 때 메시지에서 세미콜론으로 절을 이었다가, 고쳐서 다시 commit했다. 같은 날 리뷰는 ADR 0112에서 용어 불일치와 번역투 문장을 잡았다.
- 이 규칙 가운데 화살표와 세미콜론은 기호 하나로 정해지므로 검사로 찾을 수 있다. 용어 일관성, 번역투, 대시와 슬래시의 쓰임은 판단이 필요해서 지금처럼 리뷰가 맡는다.

## 결정

- 검사는 이 ADR부터 적용한다. 그 전 ADR 파일 117개에서는 43줄이 걸린다. 그중에는 규칙 자체를 설명하는 ADR 0012의 예문도 있다. 옛 ADR은 쓴 그대로 둔다.
- 건너뛰는 것은 표의 줄, fenced code, block quote, inline code, 큰따옴표 안, markdown link의 주소다.
- 경고가 아니라 오류로 낸다. Stop hook이 이 검사를 실행하므로 세션이 끝나기 전에 고치게 된다.
- Stop hook의 안내문은 skill 참조 오류만 설명하고 있었다. 그래서 모든 오류를 경로와 줄 번호대로 고치라는 문장을 앞에 더했다.
- `tests/run.sh`에 시험 셋을 더했다. 허용되는 자리의 기호는 통과하는지, 산문의 세미콜론은 걸리는지, 이 ADR보다 앞선 ADR은 건너뛰는지를 본다.

## Consequences

- commit 메시지는 검사하지 않는다. 메시지는 `git commit` 명령 안에만 있어서 Stop hook이 읽을 수 없다. commit 메시지의 위반은 리뷰가 잡는다.
- 대시는 검사하지 않는다. 규칙은 제목 구분자와 라벨 구분자로 쓰는 대시를 허용하는데, 이것을 절을 잇는 대시와 기계적으로 구별하기 어렵다.
