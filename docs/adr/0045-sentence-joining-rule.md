# 0045 — 문장 연결 규칙을 언어 무관으로 추가하고 지침 파일의 기호를 걷어냄

Claude가 쓰는 산문이 em-dash, 화살표, 세미콜론으로 절을 이어 붙여 가독성이 떨어지는 문제를 다룬다. `user/shared/rules/korean-technical-writing.md`에 "언어 무관 규칙" 절을 만들고 그 아래에 "문장 연결" 항목을 추가했다. 같은 파일과 `user/shared/CLAUDE.md` 본문에서 em-dash와 산문 속 화살표를 걷어냈다. 채택한 스킬과 과거 ADR은 손대지 않는다.

## Context

2026-09-03 측정. 이 저장소 루트의 프로젝트용 `CLAUDE.md`에 em-dash 37개, `user/shared/CLAUDE.md`에 6개, 규칙 파일에 화살표 12개, `docs/adr/` 44개 파일 전부에 em-dash, 최근 커밋 30건 중 8건에 em-dash 또는 화살표.

원인은 세 겹이다.

1. Claude Code 하네스의 "em-dash, 괄호 삽입구, 화살표 금지"는 사용자에게 보내는 최종 답변에만 걸린다. 커밋, PR, ADR, SKILL.md, 주석에는 규칙이 없었다.
2. 사용자 지침 파일 자체가 "규칙 — 이유", "A → B" 문체의 본보기였다. 모델은 명시된 규칙보다 눈앞의 문체를 더 강하게 따라 쓴다. ADR 44건 전부가 같은 꼴이 된 것이 그 증거다.
3. 규칙 파일은 어휘와 번역투만 다루고 구두점·문장 구조는 다루지 않았다. 영어 산문에는 "꾸민 산문" 절만 적용된다고 명시해 두어 영어 커밋·PR은 사실상 무규칙이었다.

## Considered Options

- **규칙만 추가.** 본보기를 두면 모델은 본보기를 따르므로 효과가 약하다. 기각.
- **규칙 추가 + 지침 파일 교정 (채택).** 두 파일 다 짧아 diff를 읽을 수 있다. 채택 스킬은 provenance가 있고 과거 ADR은 기록이라 제외했다.
- **hook 검사.** 표와 코드 블록에서 오탐이 많고 문체 모방이라는 뿌리를 못 막는다. 1·2로도 재발하면 재심한다.
- **파일 이름 변경.** 언어 무관 절이 늘어 `korean-technical-writing.md`라는 이름이 내용과 어긋난다. 그러나 [[0043-fable-5-1-learning-user-tuning]]이 이미 같은 파일에 언어 무관 절을 두는 선례를 만들었고, ADR 5건이 이 이름을 가리킨다. 이름은 두고 언어 무관 절을 한 곳에 모아 첫 줄에서 가리키는 것으로 갈음했다.

## Consequences

- 규칙 파일이 길어졌다. [[0012-korean-technical-writing-rule]]이 정한 "짧게 유지" 제약을 잠식한다. 안티패턴 두 절을 화살표 목록에서 표로 바꿔 줄 수를 상쇄했고, 표는 새 규칙이 화살표를 허용하는 자리이기도 하다.
- "이미 이 기호들로 쓰인 파일을 편집할 때도 새로 쓰는 문장에는 적용한다"는 문장이 원인 2를 직접 겨냥한다. 과거 ADR을 읽고 새 ADR을 쓸 때 문체가 전염되는 경로를 끊기 위한 것이다.
- 같은 날 정정: 화살표 항목의 첫 판은 "A를 B로 바꾼다"라는 치환 한 가지만 적어 순서·인과·대응을 놓쳤다. 화살표가 숨긴 관계를 동사로 드러낸다는 원칙으로 바꾸고 네 가지 풀이, 애매할 때는 가장 약한 관계로 푸는 규칙, 넷 이상 단계는 번호 목록, 메뉴 경로·타입 시그니처 허용을 더했다.
- `CLAUDE.md`는 구두점만 바꾸고 뜻은 바꾸지 않았으므로 `CLAUDE.md.provenance.json`에 self 항목을 추가하지 않는다.
- 성공 기준: 이 ADR 이후 새로 쓰는 ADR·커밋·PR 본문에 산문 속 em-dash와 화살표가 없다. 측정은 `grep -n "—" docs/adr/00[4-9]*.md`에서 제목 줄(ADR 번호 구분자)을 뺀 매치 수로 한다.
