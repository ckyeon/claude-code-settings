# 0012 — 한국어 기술 문서 작성 규칙을 전역 rule로 도입

Claude가 쓴 한국어 문서의 어색함을 교정하기 위해, `user/shared/rules/korean-technical-writing.md`에 전역 상시 로드 규칙을 추가한다. 범위는 **용어·번역투로 한정**하고, 문법(조사·띄어쓰기·맞춤법)은 다루지 않는다.

## Context

`~/workspace/llm-wiki`의 교정 이력(commit `652c61d`, `13a5746`, `30df69f`, `dad8293`, `08a4b74`)을 전수 조사한 결과, 실제 교정 12건+은 **거의 전부 용어·번역투 문제였고 문법 교정은 0건**이었다. 관측된 유형:

1. **번역어가 원어 개념을 왜곡** — "장치"가 물리 기구로 오독됨 → "패턴/설계"
2. **한 단어가 두 개념을 떠안음(우산어)** — "하드 강제" = 크기 상한 + 행동 개입 → 원어 분리 `hard limit` / `enforcement`
3. **한 개념에 두 단어(불일치)** — "1st-party" vs "내장", "3층" vs "3레이어"
4. **순화 과교정** — 우산어 "집행"으로 억지 통일한 것 자체가 실패였고, 원어 복귀가 더 정확했음
5. **어색한 은유** — "루프에 접다" → "루프의 동작으로 흡수한다"

llm-wiki는 이 문제를 겪으며 자체적으로 **정책(CLAUDE.md 용어 문장) + lint 스킬(탐지) + 전례집**을 진화시켰다. 이번 결정은 그중 **이식 가능한 정책 층만** 전역으로 끌어올린 것이다.

## Considered Options

**범위** — 문법 포함 vs 용어·번역투만. 증거상 문법 교정 사례가 0건이므로 **용어·번역투만**으로 좁혔다. 범위를 좁혀야 규칙이 날카로워진다.

**로딩 형식** — `paths:` 스코프 vs 전역 상시 로드. **전역**을 택했다:
- 통증이 문서·커밋·주석·PR·답변 전반에 걸쳐 있어 경로에 묶이지 않는다. `paths: ["**/*.md"]`로는 커밋·주석·채팅을 놓친다.
- path 규칙은 "매칭 파일을 **읽을 때**" 로드되므로, 새 문서를 **쓸 때**는 발화되지 않을 수 있다 — 예방 목적에 구조적으로 안 맞는다.
- Claude Code에는 **내용·언어 기반 트리거가 없다**(경로 스코프만 존재).
- 전역의 비용인 상시 context 소모는 **규칙을 짧게 + 첫 줄 자기-게이팅**("한국어 산문을 쓸 때만 적용")으로 상쇄한다.

**예방 vs 탐지** — 규칙(예방)은 확률적이라 새는 반면 lint(탐지)가 집행 층이다. 이번엔 **예방만** 넣고 탐지는 연기했다. 탐지는 스캔할 corpus·프로젝트별 용어집·판정 로그에 의존해 **이식 불가능한 데이터**를 요구하므로, 전역 규칙에 넣으면 corpus 없는 대다수 프로젝트에서 발화되지 않을 지시가 상주하게 된다. llm-wiki는 이미 자체 lint를 갖고 있다.

**glossary 분리** — glossary가 두 종류임을 확인하고 갈랐다:
- **이식 가능** = 번역투 안티패턴(이중피동, have 직역 등) → 전역 규칙에 수록
- **이식 불가** = 도메인 용어 매핑(장치→패턴, commit=커밋) → 프로젝트 국소. 전역 규칙은 컨벤션 포인터만 둔다.

## Consequences

- 모든 프로젝트의 모든 세션에 규칙이 로드된다. 짧게 유지하는 것이 유지보수 제약이 된다 — 항목을 늘리려면 상시 context 비용을 정당화해야 한다.
- 예방은 확률적이라 어색한 용어가 가끔 샌다. 이는 v1에서 **수용한 실패 모드**다: 비용이 낮고 평소 리뷰에서 잡힌다.
- **연기된 후속 아티팩트:** 재사용 가능한 용어 lint 스킬. 도입 조건은 "corpus가 커져 사람 눈이 페이지 간 드리프트를 놓치기 시작할 때" — llm-wiki가 도달했던 조건이다.
- **성공 기준:** 규칙 도입 후 새로 쓴 한국어 문서에서 (a) 안티패턴이 재발하지 않고, (b) 새 용어 도입 시 원어/병기 판단이 규칙과 일치한다. 유일한 측정 프록시는 llm-wiki의 다음 lint 패스가 잡는 *신규* 용어 불일치 건수(기준선 = 이번에 추출한 12건). 다른 프로젝트엔 lint가 없으므로 주관적 판단에 의존한다.
