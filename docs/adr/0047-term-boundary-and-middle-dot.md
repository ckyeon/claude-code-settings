# 0047 — 원칙 1의 용어 경계·병기·조사 규칙과 가운뎃점 경계를 보강

[[0046-sentence-joining-principle-first]] 직후 규칙 파일 전체를 여러 각도(빠뜨린 케이스, 규칙 간 충돌, 자기 위반, 근거 유무, 비용)로 리뷰했다. 열 항목이 나왔고 /grilling으로 그중 일곱을 이번에 넣었다. 새 줄은 없고 기존 여섯 줄이 바뀌었다. 파일은 2026-09-03 기준 54줄이다.

## 결정

- **기술 용어의 경계.** 원칙 1이 "원어 우선"만 말해 "function을 return한다" 같은 과잉 적용을 정당화할 수 있었다. 용어는 프로젝트와 도메인의 고유 개념과 코드 식별자로 한정하고, 일반 동사와 명사는 한국어로 쓴다고 적었다.
- **한글 음차.** 널리 굳은 외래어(파일, 서버)는 한글로 쓰고 경계는 프로젝트 용어집이 정한다. 34행의 "commit은 커밋으로" 예시가 이미 이 방향이었다.
- **병기 횟수.** 문서 안 첫 등장에서만 병기하고 이후엔 하나로. 원칙 3 "한 개념엔 한 용어"와의 겉보기 충돌을 없앤다.
- **원어 뒤 조사.** 발음 기준(commit을, API가). 빈도가 높은데 규칙이 없어 문서마다 갈리던 자리다.
- **원어와 자연스러움의 우선순위.** 원칙 4에 "둘이 충돌하면 뜻이 정확한 쪽을 선택한다"를 넣었다. 초안의 "부딪히면 ... 이긴다"는 사용자가 은유라고 지적해 고쳤다. 규칙 파일이 스스로 금지하는 꾸민 산문이었다.
- **무생물 주어 항목.** "의인화" 전체에서 "의지나 인식 동사"로 좁혔다. "이 함수는 X를 반환한다" 같은 동작 서술이 걸리지 않도록 표에 명시했다. 사례 수가 없는 항목이라 삭제도 검토했으나, llm-wiki 용어집에서 온 항목을 근거 없이 버리지 않기로 했다.
- **가운뎃점.** 슬래시와 같이 관계를 숨기는데 규칙이 없었고 파일 자신이 네 번 썼다. 같은 자격의 짧은 명사 나열에만 허용하고 수식어 나열에는 쓰지 않는다. 이 경계로 파일 안 "issue·리뷰 코멘트"와 "파일·메뉴 경로"가 걸려 함께 풀었다.
- **문구.** 원칙 4의 "아래 번역투를 피한다"는 뒤따르는 절 중 하나만 가리켜 "아래 안티패턴을 피한다"로. 적용 줄의 "마지막 절"은 위치 의존이라 이름만으로 가리키게 했다.

## 미룬 것

인용문의 범위, 꾸민 산문의 판별법, 프로젝트 문체 규칙과의 우선순위. 셋 다 관측 사례가 없다. 이번 리뷰의 발견 하나가 "근거 없는 항목이 가장 넓게 걸린다"였으므로, 사례가 생길 때까지 넣지 않는다.

## Consequences

- 규칙 파일이 [[0012-korean-technical-writing-rule]]의 "짧게 유지" 제약 안에서 네 번째로 늘었다. 줄 수는 같지만 원칙 1이 한 문장에서 여섯 문장이 됐다.
- 원칙 1의 "굳은 외래어" 경계를 용어집에 넘겼으므로, 용어집이 없는 프로젝트에서는 모델 판단으로 돌아간다. 이것은 [[0012-korean-technical-writing-rule]]이 수용한 실패 모드와 같다.
