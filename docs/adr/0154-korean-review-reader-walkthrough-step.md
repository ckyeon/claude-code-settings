# 0154 — 2026-11-26 korean-review에 독자가 되어 절차를 따라가 보는 단계를 받고, eval 오염을 기록

[[0153-korean-review-asks-missing-info-eval]]에 이어 사용자가 claude.ai chat에서 SKILL.md를 다시 고쳤다. 동기화된 사본을 repo에 바이트 그대로 복사했다. "## 한국어 글쓰기 규칙" 절은 바뀌지 않아 복사본 검사를 통과한다.

## 바뀐 것

- description과 첫 문단에 빠진 정보를 질문으로 낸다는 말을 더했다.
- 절차에 새 3단계 "독자가 되어 글이 안내하는 일을 따라가 본다"를 넣었다. 0153에서 2단계에 넣었던 두 문장은 이 단계로 옮겼다. 뒤 단계 번호는 하나씩 밀렸다.
- 보고를 검사하는 단계에 "'확인할 내용'의 질문은 이 검사에서 빼지 않는다"를 더했다.
- "확인할 내용"의 기준을 "독자가 그 정보 없이도 일을 끝낼 수 있으면 묻지 않는다"로 바꾸고, 한 가지 일에 딸린 빠진 정보는 한 항목에 묶게 했다.

## 결과

0153의 기준 넷 가운데 (a)는 승인 뒤에 사야 하는지, (c)는 "다음 달 급여"가 어느 달 기준인지다.

| 입력 | "확인할 내용"에서 물은 것 | grader 21개 |
|---|---|---|
| `ai-slop-guide` | (a), (a)(c), (a) | 20, 21, 20 |
| 변형 글 | 없음, 없음, 없음 | 채점하지 않음 |

- 군더더기 문장 빼기, 정보가 있는 문장 남기기, 보고 템플릿, 반영 전에 묻기는 세 번 모두 통과했다. grader 19는 (c)를 묻지 않은 두 번에서 떨어졌다.
- 변형 글 실행 하나에게 3단계를 어떻게 했는지 물었다. 실행이 끝난 뒤의 설명이라 사후 합리화일 수 있다. 그 실행은 3단계를 했고 (a)와 (c)를 찾았다. (a)는 글이 '신청하기' 다음에 '정산하기'를 놓았으니 순서대로 따라가면 된다고 추론해 넣지 않았고, 스스로 경계 사례라고 했다. (c)는 "독자가 그 정보 없이도 일을 끝낼 수 있으면 묻지 않는다"에 해당한다고 보고 걸렀다.

## 오염

- 같은 실행이 작업 폴더 이름 `eval-clean-variant`와 최근 commit 제목 "Record that the pre-change skill also asks nothing on the variant (ADR 0153)"를 보았다고 밝혔다. 이 글이 아무것도 묻지 않는 것이 기대되는 사례라고 짐작했고, 경계 판단이 그쪽으로 기울었을 수 있다고 했다.
- 이 repo에서 띄운 subagent는 최근 commit 제목 다섯 개와 작업 경로를 본다. 이번 회차의 변형 글 결과는 이 오염을 감안해야 한다. 0153의 변형 글 실행도 폴더 이름은 같았다. 다만 skill 없이 돌린 대조군은 같은 폴더 이름에서도 셋에서 넷을 물었다. 그러니 폴더 이름만으로 질문이 0개가 되지는 않는다.
- 앞으로 eval이 도는 동안에는 commit 제목에 결과를 적지 않고, 실행 폴더 이름도 설정과 기대를 드러내지 않게 짓는다. 오염을 완전히 막으려면 git repo가 아닌 폴더에서 `claude -p`로 돌린다.

## 남은 것

- 변형 글을 오염 없는 조건에서 다시 돌려, 질문이 0개인 결과가 유지되는지 본다.
- grader 19는 skill의 기준이 걸러도 된다고 한 (c)를 본다. (a)를 묻는지 보도록 바꾸는 편이 맞다.
